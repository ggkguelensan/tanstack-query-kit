# TanStack Query Kit

Переносимая архитектурная спецификация слоя серверного состояния на **TanStack Query v5** и TypeScript. Kit определяет, где объявлять запросы, ключи, мутации и композицию данных, чтобы один контракт использовался в UI, предзагрузке и SSR.

Это набор соглашений для внедрения в свой проект. Отдельного runtime-пакета устанавливать не требуется. Примеры используют React; границы ответственности применимы и к другим адаптерам TanStack Query с учётом их API.

## Четыре вида модулей

| Файл | Экспорт | Отвечает за |
| --- | --- | --- |
| `product.qk.ts` | `productQK` | Иерархию ключей кэша |
| `product.qo.ts` | `productDetailQO`, `productListQO` | Контракт чтения ресурса |
| `product.mo.ts` | `productRenameMO` | Запись и весь эффект операции на кэш |
| `product-page.aggregation.ts` | `productPageAggregation` | Композицию QO/MO и доменных функций сценария |

Consumer передаёт options целиком:

```tsx
const productQuery = useQuery({
  ...productDetailQO({ productId }),
  enabled: isPanelOpen,
  select: (product) => product.name,
});
```

QK/QO/MO принимают именованные объекты параметров; в ключах параметры также сохраняются объектами. Обязательные ID в `.qk` должны быть готовы: `.qo` проверяет их до вызова конкретного ключа и при отсутствии делает early return с `unavailableDetail()` и `skipToken`. Решение, нужен ли запрос текущему экрану, остаётся у consumer. Мутация сама согласует кэш; UI отвечает за уведомления и навигацию.

## Как использовать

1. Принять [спецификацию](SPECIFICATION.md) как соглашение проекта.
2. Разместить модули рядом с соответствующей сущностью или feature; конкретная структура каталогов не обязательна.
3. Подключить типизацию `meta.invalidates` и универсальный `MutationCache`, если используются декларативные invalidation-планы.
4. Переносить существующий код постепенно по [критериям внедрения](ADOPTION.md).

Все примеры описывают вымышленные товары и категории. Они не требуют определённого backend, роутера, state manager или монорепозитория. Базовая версия API для примеров — `@tanstack/react-query@5.104.1`; это не требование использовать последнюю опубликованную версию.
